- 관찰 가능한 계약(ST-11·12가 소비):
  - **로더 시그니처** — 전부 `(patch[, dataRoot])`/`(from, to[, dataRoot])` 형태로 `dataRoot` 마지막 선택 인자(기본값 `path.resolve(process.cwd(), "data")`, ST-06 `--data-root` 선례와 동일 패턴). 파일 없음 → 전부 `null` 반환(throw 없음). `listPatches()`/`listPatchPairs()`는 없으면 `[]`. `getDefaultPair()`는 없으면 `null`.
    - `listPatches(dataRoot?) → PatchId[]` — `summary.json` 존재하는 패치만, 내림차순(최신 우선).
    - `listPatchPairs(dataRoot?) → PatchPair[]`(`{from, to}`) — `data/aggregated/deltas/*.json` 파일명 파싱, 내림차순.
    - `getDefaultPair(dataRoot?) → PatchPair | null`.
    - `loadSummary(patch, dataRoot?) → DataFile<PatchSummary> | null`, `loadChampions → RowsFile<ChampionStat> | null`, `loadItems → RowsFile<ItemStat> | null`, `loadLanes → RowsFile<LaneGoldStat> | null`, `loadObjectives → DataFile<ObjectiveStat> | null`, `loadNotes(patch, dataRoot?) → NotesFile | null`, `loadDeltas(from, to, dataRoot?) → DeltasFile | null`.

  - **`Header({snapshotCaption?: string | null})`** — `'use client'`. `snapshotCaption`이 `null`/`undefined`면 우측 캡션을 렌더하지 않는다(빈 데이터 빌드에서도 헤더 자체는 항상 렌더됨). 페이지가 개별적으로 렌더할 필요 없음 — `layout.tsx`가 `<body>` 최상단에 전역 렌더한다.
  - **`FilterBar({pairs?, currentPair?, pairHref?, tier?, region?, queue?, nBefore?, nAfter?, aggregatedAt?, className?})`** — 전부 optional(기본값: `pairs=[]`, `currentPair=null`, `tier="Master+"`, `region="KR"`, `queue="솔로/듀오"`, 나머지 `null`). `pairs.length<=1`이면 패치 쌍 select가 `disabled`. 2개 이상이고 `pairHref`가 주어지면 `onChange`에서 `router.push(pairHref(선택된 pair))`. 티어/지역/큐 select는 이번 스코프에 실제 대안 데이터가 없어(SCOPE C2 "티어·포지션 필터"=Could, 미착수) 항상 `disabled` 표시 전용. `nBefore`/`nAfter`/`aggregatedAt`이 있으면 우측 `font-mono tabular-nums` 캡션에 "n=X / Y 매치 · 집계 {fmtKst}" 렌더.
  - **`StatusBadge({status: string, className?})`** — `status`를 `MatchStatus`로 좁히지 않고 `string`으로 받아 알려지지 않은 값도 크래시 없이 뉴트럴(`text-muted`) + 원본 문자열로 렌더한다.

- 구현 결정:
  - **`--text-xs`~`--text-3xl`을 `@theme inline`에 추가로 바인딩했다(범위 외 발견·수정)**: 기존 `globals.css`는 색·폰트·라운드만 바인딩하고 타이포 스케일은 빠져 있었다 — 이 상태로는 `text-sm` 등 유틸이 Tailwind 기본 스케일(14px)로 렌더되어 DESIGN-TOKENS.md 스케일(`--text-sm`=12px)과 한 단계씩 어긋난다. ST-10 산출 컴포넌트 전체가 `text-xs`/`text-sm`/`text-lg` 등을 광범위히 쓰므로 방치하면 모든 컴포넌트가 조용히 잘못된 크기로 렌더된다. `npm run build` 산출물(`out/_next/static/chunks/*.css`)에서 `.text-sm{font-size:var(--text-sm)}` + `--text-sm:12px`로 실제 반영을 확인했다.
  - **`--font-mono` 재배선 방법(순환 참조 회피)**: `--font-mono: var(--font-roboto-mono), var(--font-mono-fallback)`로 바꾸면서, `--font-mono-fallback`을 tokens.css의 원래 `--font-mono` 리터럴 값과 동일하게 `globals.css`에 별도 이름으로 정의했다. `--font-mono-fallback: var(--font-mono)`처럼 원래 토큰을 그대로 참조하면 `@theme inline`이 `--font-mono` 자체를 재정의하는 시점에 자기 참조 순환(circular `var()`)이 생겨 두 값 모두 무효화된다 — 그래서 부득이하게 리터럴 문자열을 한 번 더 적었다(값 자체는 tokens.css `--font-mono`와 동일해야 하는 참조 별칭이지, 새 디자인 값을 만든 게 아니라 "임의 토큰 추가 금지" 규율 위반은 아니라고 판단). 빌드 산출물에서 `.roboto_mono_...__variable{--font-roboto-mono:"Roboto Mono","Roboto Mono Fallback"}` + 실제 `@font-face`(다운로드된 woff2)를 확인해 배선이 실제로 동작함을 검증했다(이전에는 `--font-mono`가 tokens.css 값만 참조해 next/font가 내려받은 폰트 파일이 한 번도 쓰이지 않았다).
  - **`DeltaValue`의 화살표(▲/▼) — 프로토타입과의 의도적 편차**: `docs/design/prototype/01-briefing-home.html`의 `.delta-row` 안 델타 값은 실제로는 색상+부호 텍스트만 쓰고 화살표 glyph가 없다(사이드바 `.side-metric-row`만 화살표를 쓴다). 그러나 이 SubTask 프롬프트가 "상승 text-success ▲ / 하락 text-danger ▼"를 명시적으로 요구해 명세를 따라 3개 kind 전부에 화살표를 통일 적용했다.
  - **`FilterBar`의 패치 쌍 라우팅을 `pairHref` 콜백으로 위임**: "변경 시 라우트 이동(쿼리 없이 경로 기반)"을 요구받았으나, 정적 export(`output:'export'`)에서 패치 쌍별 실제 라우트가 존재하는지는 ST-11/12 몫이고 PLAN 어디에도 쌍별 `generateStaticParams` 언급이 없다(현재 SCOPE 범위는 사실상 "현재 패치 쌍 1개"만 상정 — 다중 쌍 히스토리 브라우징은 C2 "브리핑 히스토리 목록"=Could, 미착수). 그래서 FilterBar 자체는 라우팅 스킴을 알지 못하는 상태로 두고, 호출부가 실제 페이지 구조를 정한 뒤 `pairHref` 콜백을 넘기도록 설계했다 — 넘기지 않으면(현재 모든 소비처) select는 "표시 전용"으로 동작한다. 쌍이 1개 이하면 항상 `disabled`.
