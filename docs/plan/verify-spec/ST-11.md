  **`src/components/home/logic.ts`**
  - `computeHeadline(deltas: DeltasFile | null, notes: NotesFile | null): HeadlineStats` — `{noteItemCount, statCount, unannouncedCount}`. `noteItemCount`(N)은 `notes.items`를 `section∈{champion,item}`으로 필터링한 뒤 `${section}:${entity}` 키로 묶은 distinct 엔티티 수(ST-08 `matchedNoteIds`가 같은 엔티티의 노트 여러 줄을 한 묶음으로 취급하는 기준과 일치). `unannouncedCount`(U)=`status==="unannounced"` 건수. **`statCount`(M)은 `isSignificantDelta(row)`(아래) 통과 건수 — status 라벨이 아니라 q·CI를 직접 검사한다**(코디네이터 정정, 2026-09-05 — 최초 구현은 `announced-consistent`+`announced-inconsistent`+`unannounced` status 합산이었으나, `announced-inconsistent`가 "방향 불일치(유의)"와 "노트는 있지만 통계적으로 변화 없음(비유의)" 두 경우를 한데 묶어 M을 부풀리는 결함이 있었다). 입력이 둘 다 `null`이면 전부 0(throw 없음). 스탯 타일 3종("공지된 변화"·"유의 변화"·"미공지")은 각각 `noteItemCount`(N, `announcedCount`라는 별도 필드가 아니라 N 재사용)·`statCount`(M)·`unannouncedCount`(U)를 그대로 쓴다(코디네이터 확정) — 히어로 헤드라인 문구는 "패치노트는 **N개 엔티티**를 말했고, 통계는 **M개** 변화를 말합니다".
  - `isSignificantDelta(record): boolean` — `record.status!=="insufficient-sample"`(승률 n 게이트 미달은 q·CI가 유의해 보여도 무조건 비유의) `&& record.q!==null && record.q<0.10 && CI가 0을 포함하지 않음`(`ci[0]<=0 && ci[1]>=0`이면 포함으로 취급). `computeHeadline`의 M 집계가 이 함수를 그대로 재사용한다.
  - `selectTopUnannounced(deltas, limit=5)` — `unannounced` 상태만 필터링, **파일 순서를 신뢰**(재정렬하지 않음 — ST-08 `writeDeltas`가 이미 상태 우선순위→`|delta|` 내림차순으로 정렬해 기록하므로 `unannounced` 그룹은 이미 연속·정렬 상태).
  - `selectAnnouncedPreview(deltas, limit=5)` — **`matchedNoteIds.length>0`인 행을 `entityType:entityKey`로 그룹핑해 그룹당 대표 1행만** 뽑아 `|delta|` 내림차순으로 정렬한다(2단계 코디네이터 정정, 2026-09-05). 1차 정정(status 필터 → `matchedNoteIds` 필터로 교체 — "짝은 있지만 승률 n 게이트 미달"인 행은 status가 `insufficient-sample`로 갈려 status 필터에서 누락됐다. 프로토타입 공지 대조 미리보기 4번째 행 "폭풍갈퀴... n<200... 표본 부족" 예시가 정확히 이 케이스)까지는 유지하되, **2차 정정으로 엔티티 단위 dedupe를 추가**했다 — 아래 "구현 결정"의 렌더 검증 결함(같은 엔티티의 지표별 행이 상위 5자리를 전부 차지해 미리보기가 같은 노트 문장만 5번 반복) 참고. 대표 선정: `isAllScopeChampionRow`(id 세그먼트 수로 챔피언 scope=all 여부 판별) 우선 → 그중(또는 scope 구분이 없는 entityType은 전체 중) `|delta|` 최댓값.
  - `formatNotePreviewText(note, matchedNoteCount, fallbackEntityName): string` — `"{note.entity}[ · {note.skill}] — {note.summary}[ 외 {matchedNoteCount-1}건]"`(코디네이터 지시, 2026-09-05 — 프로토타입 "나서스 기본 지속 효과 생명력 흡수 12/18/24% ⇒ 10/15/20%"처럼 엔티티명이 문장 맨 앞에 오도록). `skill===null`이면 가운뎃점 세그먼트를 생략(코디네이터 원문의 `{skill ??   - `metricKind(metric): DeltaKind` — `pickRate|banRate|winRate|adoptionRate`→`"pp"`, `avgDurationSec|firstSec`→`"sec"`, 그 외(`goldAt10`·`goldAt14` 등)→`"gold"` 폴백.
  - `formatMetricValue(value, metric)`/`formatObservedSummary(record)` — kind별 절대값/델타 표시 텍스트.
  - `resolveCause(record): {mode:"verified"|"unverified", text}` — `causes[0]` 없음→`{unverified, "근거 미확인"}`, 있고 미검증→`{unverified, "{text} — 근거 미확인"}`, 검증됨→`{verified, text}`(프로토타입 `.delta-cause` 5개 행 표기 그대로).

  - **공지 대조 미리보기 선택 기준을 status 필터에서 `matchedNoteIds` 유무로 교체했다(같은 정정 세트)**: status 기반 필터(`announced-consistent`/`announced-inconsistent`)는 "노트와 짝지어졌지만 승률 n 게이트 미달이라 `insufficient-sample`로 분류된" 행을 놓친다(ST-08 verdict 1번 분기가 매칭 여부와 무관하게 최우선 적용되기 때문). `matchedNoteIds.length>0`으로 직접 걸러야 이런 행도 포함되며, 이는 프로토타입 `01-briefing-home.html`의 4번째 공지 대조 행("폭풍갈퀴... n<200... 표본 부족" 배지)이 정확히 보여주는 패턴이다 — status 필터였다면 이 프로토타입 예시 자체를 재현할 수 없었을 것.
  - **공지 대조 미리보기를 `|delta|` 기준 재정렬한 이유**: ST-08 `writeDeltas`는 상태 우선순위 그룹(예: `announced-inconsistent` 전체가 `announced-consistent` 전체보다 앞)별로 정렬하지, 두 상태를 합쳐 `|delta|`로 정렬하지 않는다. ST-11 프롬프트가 명시적으로 "announced-* 중 |delta| 큰 순"을 요구해 `selectAnnouncedPreview`에서만 병합 재정렬했다(미공지 목록은 이미 단일 상태만 보므로 파일 순서 그대로 신뢰).
