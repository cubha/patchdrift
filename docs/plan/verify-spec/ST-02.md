### VERIFY-SPEC — SubTask ST-02

- 기준선 요구사항: "Riot API 클라이언트 — fetch + bottleneck chain(20/1s ⟵ 100/120s, minTime·maxConcurrent), 429 `Retry-After`·5xx 지수 재시도, 타입드 엔드포인트(league-v4 challenger/grandmaster/master entries, match-v5 ids by puuid(startTime/endTime/queue/count), match, timeline)" (PLAN ③ ST-02 행). 배치 프롬프트 원문: bottleneck 2단 체인(app 20/1s·maxConcurrent 4 ⟵ 전역 100/120s), 429는 Retry-After 대기 후 최대 5회 재시도(없으면 지수 백오프 1s→), 5xx/네트워크는 지수 백오프 3회, 404는 null(매치 없음), 403은 즉시 throw(키 미포함), 방법 리밋 헤더는 로깅 콜백만, `toMatchSlim` 순수 함수, D+1 라이브 스모크 필수.

- 변경 파일:
  - `src/pipeline/collect/riot-client.ts` (수정 — 스텁 → 전체 구현)
  - `src/pipeline/collect/__tests__/riot-client.test.ts` (신규, 20 케이스 — toMatchSlim 6 + 클라이언트 retry/limit/endpoint 14)
  - `src/__fixtures__/riot-match-26-17.json` (신규 — 라이브 스모크 실응답을 트리밍한 커밋 fixture, puuid만 익명화)
  - `scripts/smoke-riot.ts` (신규 — D+1 라이브 스모크, 캐시 재사용 지원)

- 관찰 가능한 계약:
  - `createRiotClient({apiKey, platform, region, fetchImpl?, sleepImpl?, appLimiterOptions?, globalLimiterOptions?, onRateLimit?})` → `{getLeagueEntries, getMatchIdsByPuuid, getMatch, getMatchTimeline, dispose}`.
  - `getLeagueEntries(tier, queue='RANKED_SOLO_5x5')` → `LeagueEntrySlim[]`(`{puuid, summonerId, leaguePoints, wins, losses}`). entries에 `puuid` 있으면 그대로, 없으면 `summonerId` → summoner-v4로 폴백 해석. 404는 즉시 throw(재시도 없음).
  - `getMatchIdsByPuuid(puuid, {startTime?, endTime?, queue=420, type='ranked', start=0, count=100})` → `string[]`. 쿼리 파라미터가 URL에 그대로 반영됨(테스트로 확인).
  - `getMatch(matchId)`/`getMatchTimeline(matchId)` → raw DTO 또는 `null`(404 한정). 그 외 비정상 상태(403/5xx 예산초과 등)는 throw.
  - 429: `Retry-After` 헤더(초) 있으면 그 값만큼 대기 후 재시도(최대 5회, 6번째 실패 시 throw). 헤더 없으면 `1000 * 2^attempt` ms 지수 백오프.
  - 5xx/네트워크 예외: `1000 * 2^attempt` ms 백오프로 최대 3회 재시도, 초과 시 throw.
  - 403: 재시도 없이 즉시 throw, 에러 메시지에 `apiKey` 값을 포함하지 않음(테스트로 확인).
  - `X-Riot-Token` 헤더로 키 전달, URL에는 포함하지 않음.
  - `onRateLimit(snapshot, url)` 콜백에 `X-App-Rate-Limit*`·`X-Method-Rate-Limit*` 헤더값을 그대로 전달(로깅 전용 — 재시도 판단에 쓰지 않음).
  - `toMatchSlim(raw: RiotMatchDto): MatchSlim` — 순수 함수. `participants.length !== 10` 또는 `teams.length !== 2`면 throw(조용히 자르지 않음). `teams[].objectives.horde` → `MatchTeamObjectives.grubs`로 매핑, `atakhan`/`champion`/`inhibitor` 등 계약 외 키는 버림. `gameVersion` → `canonicalPatch()`로 `patch` 필드 채움.
  - `dispose()` — bottleneck 두 리미터의 타이머(reservoirRefreshInterval)를 정리한다. 호출하지 않으면 Node 프로세스가 종료되지 않는다(스모크 스크립트 `finally`에서 호출).

- 구현 결정:
  - **라이브 스모크 선행 원칙(advisor 합의)**: `toMatchSlim`/wire DTO 타입은 실제 응답을 받은 뒤 확정했다. 클라이언트 골격(리미터·재시도·4개 엔드포인트)을 먼저 작성 → 스모크 4회 호출 실행 → 응답 구조 확인 → `RiotMatchDto`/`toMatchSlim` 최종 작성 순서로 진행했다.
  - Riot wire DTO(`RiotMatchDto` 등)는 `riot-client.ts` 내부 전용이며 export하되 `types.ts`에는 두지 않는다 — "도메인 타입은 types.ts에만" 규칙은 도메인 타입 대상이고, wire 포맷은 collect 계층 소관(advisor 합의).
  - `teams[].objectives.horde`(void 유충)만 `grubs`로 매핑한다. 라이브 확인 결과 `atakhan`(2025+ 신규 오브젝트)·`champion`·`inhibitor` 키도 존재하지만 PLAN F1 계약(`{baron, dragon, riftHerald, tower, grubs?}`)에 없으므로 의도적으로 버린다 — 필요 시 별도 SubTask에서 계약을 갱신해야 한다.
  - 429/5xx 재시도 지연은 `sleepImpl` 주입으로 테스트에서 실제 대기 없이 검증한다(대기 시간 배열을 기록해 assert). 리미터는 `appLimiterOptions`/`globalLimiterOptions`로 `minTime:0` 등 오버라이드 가능하게 옵션화했다(스펙 요구사항).
  - `getLeagueEntries`가 `summonerId`도 `puuid`도 없는 entry를 만나면 throw한다 — 무근거로 빈 puuid를 채우지 않는다는 원칙 적용(F-없음이지만 CLAUDE.md "무근거 문장은 회색" 원칙과 동일 취지의 명시적 실패).
  - stub/fallback 없음. `console.log`는 `scripts/smoke-riot.ts`에서만 사용(verify.sh 규칙 준수).
